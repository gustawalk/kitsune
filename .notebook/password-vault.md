# Password storage providers

- `src-tauri/src/model.rs:ConnectionConfig` adds `credential_store`, defaulting to `operatingSystem` for legacy saved connections. Plaintext `password` remains excluded from serialization. `src/lib/validation.ts` normalizes the matching frontend field and validates vault status responses.
- `src-tauri/src/security/passwords.rs` routes credential load/save/removal to the explicit provider; no plaintext fallback exists. `commands.rs:resolve_password()` retrieves saved credentials only when Remember password is enabled. Blank edits preserve passwords; changing providers requires re-entry and retains entries in the previous provider.
- `src-tauri/src/security/vault.rs` encrypts the complete credential map in one `credential_vault/default` metadata document. Version 1 uses Argon2id (64 MiB, 3 passes, 1 lane), a random 16-byte salt, and XChaCha20-Poly1305 with fresh random 24-byte nonces. Application/version/KDF context and salt are authenticated. Creation and updates use SQLite compare-and-swap so concurrent app instances fail safely instead of losing entries.
- `src-tauri/src/state.rs:AppState` owns the in-memory zeroizing key behind a mutex. Lock/exit drops it. Plaintext serialization buffers and decrypted map values are zeroized. Vault IPC setup/unlock moves the master password into a zeroizing wrapper and returns only initialized/unlocked flags. Lifecycle IPC never returns passwords; see the explicitly requested autofill endpoint below.
- `src/components/PasswordVault.tsx` provides setup, confirmation, unlock and lock inside ConnectionDialog and Settings. Master fields are component-local and cleared after requests; Enter does not submit the enclosing form. Existing database sessions stay connected when the vault is locked. There is no master-password recovery.

Validation: Rust vault tests cover restart/unlock, incorrect master passwords, salt/ciphertext/nonce tampering, nonce freshness, encrypted persistence, locking, deletion and stale writes. IPC tests exercise saved connections without any OS keyring. Browser tests cover creation/confirmation, errors, clearing secret fields, Enter, and choosing the local provider in ConnectionDialog. User vault creation is left to the user; tests use temporary databases only.

Unlock feedback fix: shared `useRemote` invalidation caused competing vault status requests to cancel one another when Settings and ConnectionDialog were both mounted. A browser reproduction left only one of two panels unlocked after a successful action. `PasswordVault` now publishes the authoritative mutation response to both panels directly, with no shared status cache; late initial reads are ignored. Regression browser checks cover both unlock and lock plus delayed initial responses. ConnectionDialog indicates that blank password fields reuse saved credentials and disables vault-dependent actions until unlocked. An ignored PostgreSQL integration test (`postgres_vault_password_survives_session_restart`) takes disposable credentials from `KITSUNE_VAULT_TEST_*`; it verified password-free saved configs reconnect after resetting in-memory vault state, unlocking, and applying a blank edit. It never touches the user vault.

Vault autofill: `commands.rs:vault_connection_password` reads only a persisted connection that remembers a password in `localVault`, requires the vault key, and returns its password or null. ConnectionDialog uses direct `api()` calls after unlock or opening an already-unlocked vault, retains the result only in the masked form field, and ignores late responses after lock/provider changes/unmount. Manual edits made while fetching are preserved. Locking clears autofilled values. Never use `useRemote` or global storage for this secret response. IPC tests cover locked, missing, deleted, OS-provider and non-remembered entries; browser checks cover auto-fill, reopen, masking, lock clearing and races.

Credential-provider parity: `commands.rs:connection_password` reads the persisted provider for either keyring or local vault; the legacy `vault_connection_password` endpoint remains vault-only. `ConnectionDialog` deduplicates secret fetches within the mounted form (including StrictMode), ignores stale/manual-edit responses and clears autofilled values on lock/provider changes. No secret goes into shared caches. The placeholder no longer suggests leaving passwords blank.

Quick connect: `Sidebar.tsx` opens `components/QuickConnect.tsx` for disconnected saved connections. Saved credentials stay in Rust via existing connect/password resolution. The compact dialog prompts only for a password or vault unlock when needed, with a settings escape hatch. Initial attempts deduplicate under StrictMode. Already-connected reconnect actions retain the settings path. `features/Connections.tsx:connectSaved()` refreshes connection/read-only state after success.

URL import: `lib/connection-url.ts:parseConnectionUrl()` decodes supported PostgreSQL/MySQL/MariaDB/SQL Server URIs into ordinary fields plus a separate password. `ConnectionDialog` masks and clears the raw URL on import; rejects unsupported/duplicate options instead of silently dropping semantics. Supported query options: host, port, user, password, dbname/database, ssl/sslmode, sslrootcert/sslcert/sslkey. No raw URL is persisted.
